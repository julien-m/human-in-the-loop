# Internal UI contract

Implement `src/ui.mjs` and `src/ui.css`. Export `mount(root, backend)` returning `{refresh(), destroy()}` for DOM tests. The browser entry is `src/app.mjs` importing `App` from `@modelcontextprotocol/ext-apps`, mounting after connect. Exportable DOM code must not import the SDK itself.

Backend: `call(name,args)` resolves decoded structuredContent or throws a coded error; `canSend()` feature-detects the MCP host message capability; `send(text)` calls the host message bridge. Read identity from tool result `{scope, uiToken}` (uiToken is hidden `_meta`); entrypoint without these shows an unbound state, never picks a recent conversation. `mount(root,backend, binding)` is acceptable, with optional binding; expose `bind(binding)` on return for new tool results. No navigation to another conversation from this UI.

App-only tools require `{scope, uiToken}`. `human_read` returns `{revision,working,ended,tasks,pending,previous}`. A task has `{id,number,title,why,done_when,kind,options,state,revision,response}`. Kinds: do/answer/choose. States: open/done/rejected/withdrawn. `pending` contains response objects `{id,task_id,number,title,state,text,delivery}`; delivery pending/accepted/unknown. Only open tasks and responses without agent acknowledgement count as visible. `previous` lists ended sessions in the same project as `{threadId,count}`.

`human_respond`: binding plus `{taskId,expectedRevision,actionId,action:done/answer/choose/reject,text?,allowSecret?:boolean}`. Returns `{response,snapshot}`. `actionId` is a stable random UUID per click and retained for safe retry; changed payload requires a new ID. Store rejects `secret_held`, `revision_conflict`, `not_open`, `invalid_choice`, `invalid_action`. Preserve draft on errors; `secret_held` warns and requires explicit user action before retry with allowSecret.

`human_delivery`: binding plus `{responseIds:[...],status:accepted/unknown}` returns snapshot. `human_read` never marks delivery or acknowledgement. Response IDs must be delivered together in a user message, formatted with title, task number, response and stable response ID, then call human_delivery accepted. Failed/ambiguous bridge -> unknown, show manual recovery, never automatically resend. A request already acknowledged disappears from pending. Agent acknowledgement, not UI delivery, finalizes it.

Automatic delivery: after user answers while idle, send pending responses if host supports message; while working, save. Poll every 2 seconds, one in-flight refresh, pause hidden and during edits/mutations. On working->idle, send pending only when no open tasks remain. Send now allows explicit immediate send while working. No host message capability -> copy text plus saved/pending status, no simulated success. Preserve drafts, avoid automatic retries of unknown/accepted deliveries. Pin sending state synchronously to avoid duplicate sends during a refresh. Native bridge acceptance is distinct from agent processing.

`human_adopt`: binding plus `{fromThreadId,actionId}`. Only ended same-project sessions; returns snapshot. Show an explicit recovery button; never adopt live sessions automatically.

UI: Human in the loop, section My tasks / Mes tâches (French preferred), open count; three task kinds; Done, free multiline response, 2–4 choices, reject with reason, Hide; pending response state and Send now. Escape untrusted values with DOM textContent. Compact responsive panel; local CSS, system fonts, no remote assets. Keyboard and accessible names. No private examples. Preview fixtures must be clearly labelled Demo.
